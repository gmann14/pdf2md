# Implementation plan — pdf2md

Regenerated by the Forge plan pass from `docs/` ↔ code gap analysis. Hand-edits
survive only until the next plan pass; durable direction belongs in `docs/`.

This pass keeps only open work. Previously shipped work is summarized in
"Verified-present" so it does not get re-planned as a gap.

Item statuses: `done`

## Context

The project is far along. Phase 1 MVP, Phase 1.5 (`@pdf2md/core@0.2.0`), and
Phase 1.6 (`@pdf2md/mcp@0.1.0` + Claude skill) are shipped and published. CI
exists under `.github/workflows/ci.yml` and gates lint, typecheck, unit tests,
and corpus smoke tests on PRs. The conversion engine already implements the
core spec contract (`ConversionResult`, stable codes, `AbortSignal`, progress,
metadata/YAML front matter) plus most Phase 2 quality features.

The gaps below are the verified remainder. Each missing/partial claim was
confirmed by code search before being added.

## pdf2md#4 — Tagged-PDF fast path via `getStructTree()`
- **Description:** When a PDF exposes a structure tree (`page.getStructTree()`), use it for semantic-accurate conversion instead of pure heuristics. Confirmed absent: no `getStructTree`/`StructTree` reference in core or web code.

- **Complexity:** high
- **Spec:** `docs/spec.md` Phase 2 feature 8 "Tagged PDF fast path"; Phase 2 checklist.
