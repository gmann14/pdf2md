# Implementation plan — pdf2md

Regenerated by the Forge plan pass from `docs/` ↔ code gap analysis. Hand-edits
survive only until the next plan pass; durable direction belongs in `docs/`.

Item statuses: `open | in-progress | escalate | blocked | done`

## Context

The project is far along. Phase 1 MVP, Phase 1.5 (`@pdf2md/core@0.2.0`), and
Phase 1.6 (`@pdf2md/mcp@0.1.0` + Claude skill) are shipped and published. The
conversion engine already implements the full spec contract (`ConversionResult`,
stable codes, `AbortSignal`, progress, metadata/YAML front matter) plus most of
Phase 2 (tables, code blocks, multi-column, multi-file drop). Quality sits at
~9.0/10 across 28 corpus PDFs with 97 unit tests. The site is live on Vercel
with SEO meta, JSON-LD, OG image, how-to content, and a privacy page.

The gaps below are the verified remainder, prioritized for a launch-imminent
project. Each "not implemented" claim was confirmed by code search, not assumed.

---

## pdf2md#1 — Day-1 observability: error tracking + privacy-friendly analytics
- **Description:** Wire Sentry (client-side error tracking) and a cookie-free analytics provider (Plausible/Fathom) into `apps/web`, honoring the telemetry rule (never send file contents, text, filenames, or PDF metadata off-device).
- **Acceptance criteria:**
  - Client PDF-parse exceptions surface in Sentry with the stable `ConversionCode` as a tag; no file bytes, extracted text, or filenames in any event payload.
  - Anonymous aggregate events only: conversion count, page-count bucket, file-size bucket, success/failure, output action (copy vs download).
  - Analytics is cookie-free (no consent banner); privacy page copy stays accurate to what actually ships.
  - `pnpm build` static export still succeeds; no analytics/Sentry code runs during SSG.
- **Complexity:** med
- **Spec:** `docs/spec.md` §Analytics & Observability (Day 1); Phase 1 checklist "Plausible analytics + Sentry error tracking" (open).
- **Status:** done

## pdf2md#2 — CI pipeline: gate lint/typecheck/tests + corpus smoke test on every PR
- **Description:** Add `.github/workflows` running lint, typecheck, unit tests, and a conversion smoke test against the launch corpus on every PR. No workflow dir exists today.
- **Acceptance criteria:**
  - CI runs `pnpm lint`, `pnpm typecheck`, `pnpm test` and fails the PR on any non-zero exit.
  - A corpus smoke step asserts at minimum: no crash, correct explicit-failure classification, and presence of heading/list/link output on golden samples.
  - Runs on PRs targeting `main`; green required before merge (supports the Forge `branch-pr` policy).
  - Caches pnpm store for reasonable run time.
- **Complexity:** med
- **Spec:** `docs/spec.md` §Regression & CI; Phase 1.5 checklist "Add CI pipeline for lint, typecheck, tests, and corpus smoke tests" (open).
- **Status:** open

## pdf2md#3 — Autoresearch runner scaffold + first overnight quality pass
- **Description:** Create the `autoresearch/` runner (baseline snapshot, experiment log, compare-vs-baseline PASS/FAIL) described in `docs/autoresearch-plan.md`, then run the first pass on a branch targeting code-block detection and link extraction. No `autoresearch/` dir exists; the four `test-corpus/evaluate*.ts` scripts it wraps do exist.
- **Acceptance criteria:**
  - `autoresearch/` contains `baseline.json`, `experiments.jsonl`, `latest-summary.md`, `run-quality-suite.ts`, `compare-results.ts` per the plan.
  - Runner executes the four evaluation commands, parses per-dimension + combined scores, snapshots git SHA/branch, and prints PASS/FAIL against the acceptance formula.
  - Honors the plan's guardrails: no npm publish, no deploy, no PDF/result deletion, no scoring-weight changes to flatter results.
  - First accepted experiment improves combined score ≥0.05 (or a target dimension ≥0.3) with no doc dropping >0.3; logged to `experiments.jsonl`.
- **Complexity:** med
- **Spec:** `docs/autoresearch-plan.md` (whole doc); Phase 2.5 checklist (open).
- **Status:** open

## pdf2md#4 — Tagged-PDF fast path via getStructTree()
- **Description:** When a PDF exposes a structure tree (`page.getStructTree()`), use it for semantic-accurate conversion instead of pure heuristics. Confirmed absent: no `getStructTree`/`StructTree` reference anywhere in core or web.
- **Acceptance criteria:**
  - Detect presence of a usable struct tree; fall back cleanly to the existing heuristic pipeline when absent or unusable.
  - On tagged PDFs, headings/lists/paragraphs derive from tags; output quality on a tagged corpus sample is equal or better than the heuristic path (no regression on untagged PDFs).
  - New unit tests cover tagged and tag-fallback cases; `pnpm test` and `pnpm typecheck` pass.
- **Complexity:** high
- **Spec:** `docs/spec.md` Phase 2 feature 8 "Tagged PDF fast path"; Phase 2 checklist (open).
- **Status:** open

## pdf2md#5 — Comparison view: original PDF render beside Markdown
- **Description:** Render the source PDF (PDF.js canvas) alongside the Markdown output for spot-checking. Confirmed absent: no canvas/`page.render`/`getViewport` usage in web.
- **Acceptance criteria:**
  - Toggleable side-by-side view on desktop; stacks vertically on mobile per the SEO/mobile rule.
  - Canvas render stays client-side and lazy (does not regress initial LCP); reuses the already-parsed document where possible.
  - Keyboard-reachable and labeled, consistent with the accessibility baseline.
- **Complexity:** med
- **Spec:** `docs/spec.md` Phase 2 feature 11 + "Use It Ourselves" #6; Phase 2 checklist (open).
- **Status:** open

## pdf2md#6 — JSON structured-output mode + configurable chunking
- **Description:** Add an output mode returning structured sections (hierarchy, page numbers per chunk) and chunking by page/heading/token count, for RAG workflows. Confirmed absent in core (`outputFormat`/`chunk` unused).
- **Acceptance criteria:**
  - `convert()` supports a structured/JSON output option without breaking the existing `ConversionResult` markdown contract (additive, not a breaking API change).
  - Chunking modes: by page, by heading, by approximate token count; each chunk carries section + source-page metadata.
  - Covered by core unit tests; CLI exposes the mode; `pnpm test`/`pnpm typecheck` pass.
- **Complexity:** med
- **Spec:** `docs/spec.md` Phase 5 + "Use It Ourselves" #3/#4.
- **Status:** open

## pdf2md#7 — Paste-PDF-from-clipboard keyboard shortcut
- **Description:** Support Ctrl/Cmd+V to paste a PDF from the clipboard into the converter (Ctrl+C to copy output already exists via OutputPane). Confirmed absent: no paste handler in components.
- **Acceptance criteria:**
  - Pasting a PDF blob anywhere on the converter triggers conversion through the same path as drag-drop/file-picker.
  - Non-PDF clipboard contents are ignored gracefully (no error toast spam).
  - Announced for screen readers consistent with the accessibility baseline.
- **Complexity:** low
- **Spec:** `docs/spec.md` "Use It Ourselves" #5 keyboard shortcuts.
- **Status:** open

## pdf2md#8 — Google Search Console verification + launch readiness
- **Description:** Add the GSC verification token/meta and finalize launch prerequisites (sitemap reachable, OG/meta validated). Mostly config + non-code launch execution (PH/HN/Reddit) tracked here for visibility.
- **Acceptance criteria:**
  - GSC verification present (meta tag or DNS) and property verified; sitemap submitted.
  - No code regression to existing SEO meta/JSON-LD/OG.
  - Launch-execution sub-items (PH/HN/Reddit posts) tracked but recognized as non-code; not gated by CI.
- **Complexity:** low
- **Spec:** `docs/spec.md` Phase 3; `docs/launch-plan.md` Launch Week; Phase 3 checklist (open).
- **Status:** open
